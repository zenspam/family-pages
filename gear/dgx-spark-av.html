Spark 這一側

四個 USB-C，能用的三個

最左邊那個是 240 W 供電入口，不要插週邊。其餘三個資料埠約 20 Gbps，鏡頭一個、音箱一個、直插就好，不必 hub。真要 hub，選自帶電源的。

沒人查到 每個資料埠能供多少電，NVIDIA 沒寫。會吃 5V/2A 的音箱（Anker PowerConf S330 那類）別買；Jabra 有電池不受影響。

Linux 免驅動的條件

鏡頭要 UVC，音箱要 USB Audio Class。Ubuntu 24.04 核心內建 uvcvideo 和 snd-usb-audio，aarch64 一樣有。羅技和 Jabra 的按鍵、藍牙雙模、AI 取景這些靠廠商軟體的功能在 Linux 沒有，但音訊和影像本體會通。

DGX OS 偏伺服器導向，可能沒裝聲音服務。先裝再插：

sudo apt install pipewire pipewire-audio wireplumber v4l-utils alsa-utils
arecord -l ; v4l2-ctl --list-devices

面對面的實務

回音消除靠音箱，不靠系統

會議音箱在自己的晶片裡拿喇叭輸出當參考消回音，送進 Linux 的已經是乾淨聲音。六席一致。分開買麥克風加喇叭就得靠 PipeWire 的軟體回音消除，對延遲不穩的 USB 路徑很敏感，調不好會自聽自答。

麥克風陣列：一公尺內不是重點

三席說 60 到 100 公分單顆全指向就夠，陣列是給兩三公尺會議室的；兩席說 Spark 風扇和鍵盤聲會讓四麥有感。分歧留著。花錢順位：全雙工先，回音消除品質次之，陣列最後。

鏡頭：視角 78 到 90 度，低光比 4K 重要

這個距離要看到頭肩和雙手，78 到 90 度剛好。晚上室內是常態，感光元件比解析度值錢；一盞五百元的桌燈比升級鏡頭便宜。4K 只多吃 USB 頻寬。

延遲在哪裡

USB 音訊和鏡頭加起來不到 50 毫秒，不是瓶頸。真正決定像不像人的是這一串：判斷你講完了沒（300 到 700 毫秒，最大一段，太短截話、太長很呆）、語音轉文字、模型第一個字、語音合成第一塊聲音。影像那條（人臉、手勢）獨立跑、只當上下文，不要串進語音的關鍵路徑。
