jvg 搬家 spec — 把「JSON／valkey／gitea」派工流程移到另一台電腦給 agent 開發

寫於 2026-09-08 13:2x 台北。來源：Ray 語音「我要將 jvg 這套 flow 轉移到其他電腦上給 agent 開發，你把 spec 寫出來」。讀者＝要在新機器上把它蓋起來的 agent；每個零件寫「做什麼、介面是什麼、搬家要換什麼、怎麼驗」。現行實作的檔名只當參考，不是要照抄。

0. 一句話

一張活＝一張票（gitea）＋一筆隊列訊息（valkey）＋清單上一行（JSON）。教練只開票、派單、跑驗收；席位從隊列拉活、在共享目錄交件；事件流把「接了／做完／死了」寫回清單。passes 只准驗收指令跑綠翻，人手不能翻。

1. 角色與機器

角色 做什麼 現行住哪 搬家後
教練（coach） 開票、派單、sync、check、finish Sai 容器（沒掛共享目錄） 任一台能連 valkey＋gitea 的機器；掛得到共享目錄就不需要橋
橋（bridge） 替教練在共享目錄落 spec、投隊列 qqs 容器 jvg_bridge.py 教練掛得到共享目錄就省掉；掛不到就保留
席位（worker）×N 拉活、跑模型、交件、發事件 每席一隻 02_pull_worker.py＋一個本機 /control HTTP 執行端 每席一隻 worker＋任一個「收 prompt 回結果」的執行端（pi --mode rpc、claude -p、任何 HTTP）
看守（optional） 卡單告警、心跳、票表 stall_watch.py、heartbeat/、tickets_page.py 第二階段再搬

共用基礎設施：一台 valkey（Redis 相容，要密碼）、一個 gitea（repo＋token）、一個所有席位都掛的共享目錄（現行 /team）。

2. 三份狀態檔（J）

全住 HS_DIR（環境變數，預設 /app/handoff），git 追蹤。

feature_list.json：{"features":[…]}，每項：

{"id":"line-push-allowlist",
 "behavior":"一句話說做完會怎樣（給票的標題與 spec 正文）",
 "check_template":"dgx:cd {out_dir} && test -s REPORT.md && <可執行的驗收指令>",
 "check":"（dispatch 後把 {out_dir} 代入 check_template 的結果）",
 "passes":false,
 "ticket":"#299","opened_at":"2026-09-07T20:36:35+08:00",
 "task_id":"jvg.line-push-allowlist.09071307",
 "out_dir":"/team/runs/20260907/jvg-20260907/jvg.line-push-allowlist.09071307",
 "stream_id":"1788786446202-0","status":"queue_task_done"}

規則：passes 只由 hs check <id> 跑綠翻 true；hs verify 抓人手翻的。check 以 dgx: 開頭＝要在共享目錄那側跑（教練掛不到時交給橋）；沒前綴＝教練本機跑。{out_dir} 佔位符 dispatch 時代入。

progress.log：只增不改，一行一事，時戳台北：2026-09-08T08:42:01+08:00 <事>。hs note "<事>" 寫。

handoff.json：{"current":{"feature_id","ticket","stopped_at","since"},"next":[],"blocked":[],"updated_at","last_finish_at"}。hs set-current <id> <#票> "<停在哪>" 寫。

3. 教練命令（hs）

命令 做什麼 對外呼叫
open <id> 開票；票號寫回清單 gitea POST /repos/{repo}/issues，title [jvg] <behavior 前 80 字>，body＝behavior＋「驗收（機器判）」程式碼塊＋來源
dispatch <id> [--timeout 1500] [--owners only:<seats>] [--detail "<只做這一件>"] [--again] 沒票不派；組 spec；投橋；等回執 valkey XADD jvg:dispatch；XREAD BLOCK jvg:dispatched 等 task_id 對上
sync 事件流 → 清單 status（做完≠通過） valkey XREVRANGE nova:events COUNT 3000，只認 queue_task_*／owners_*
check <id> 跑 check；綠翻 passes 本機 shell，或 dgx: 交橋
note／set-current／status／nag 三檔讀寫；開機印停在哪；兩小時沒動就喊 無
finish -m "<msg>" 三痕跡（新 note、handoff 更新、有東西可 commit）缺一拒；齊了 git commit git
hands <#票> "<理由>" 教練自己改程式檔的例外憑證（配 PreToolUse hook） 無

Gitea 憑證：token 檔（現行走共享目錄的 creds 檔＋whoami_cred.py；新機器改環境變數 GITEA_URL／GITEA_REPO／GITEA_TOKEN）。valkey 密碼：檔案（現行 /app/.valkey_pw），新機器改 VALKEY_HOST／VALKEY_PORT／VALKEY_PW。現行程式碼把這些寫死，搬家第一件事是把常數抽成環境變數。

4. 隊列協定（V）

4.1 教練 → 橋：stream jvg:dispatch

欄位：task_id（jvg.<feature_id>.<MMDDHHMM>）、ticket、timeout（秒）、expected（逗號分隔的產物相對路徑，至少 REPORT.md）、verify、flow_id（jvg-YYYYMMDD）、spec_md（整份 spec 正文）、from、owners（空或 only:<consumer,…>）。 橋回 stream jvg:dispatched：task_id, ok, out_dir, stream_id 或 task_id, ok=false, error。

4.2 橋 → 隊列：01_submit_task.py

  1. 落 <共享>/runs/<YYYYMMDD>/specs/<task_id>.md。
  2. 建交付目錄 <共享>/runs/<YYYYMMDD>/<flow_id>/<task_id>/：README.md（任務摘要、判準、重跑指令）、00_prompt.txt（送達版 prompt 全文＝spec＋執行紀律）、00_flow.lisp（可省）、in/。
  3. XADD tasks:low：task_id, spec_path, out_dir, timeout_s, expected_outputs, run_id[, tier, orphan_idle, owners]。
  4. 印 out_dir 與 stream id（橋轉回 jvg:dispatched）。

4.3 席位 worker（每席一隻，consumer 名＝席位名）

  • consumer group on tasks:low；心跳 SET worker:hb:<consumer> EX 30 每 15 秒。
  • XREADGROUP BLOCK 5000 COUNT 1；沒新活每 3 輪讀自己的 PEL 撿未 ack。
  • 認領即 XADD nova:events kind=queue_task_taken consumer task_id msg_id。
  • owners 不含自己 → 重投隊尾（帶 first_requeue_at，只寫一次）；死信三種理由：目標席不在心跳名單／等超過 T／副本超過 200。
  • 冪等：out_dir/manifest.json 已存在 → XACK＋kind=queue_task_skipped。
  • 執行：把 00_prompt.txt 送本機執行端（現行 POST http://127.0.0.1:<port>/control {"action":"cli","prompt":…,"timeout":…}，HTTP timeout＝timeout+30）。執行端可換：任何「收 prompt、在 out_dir 工作、回 ok/非 ok」的東西。
  • 驗產物：expected_outputs 逐項存在且非空；沒給就檢 out_dir 非空。
  • 失敗：HINCRBY task:attempts:<task_id>；kind=queue_task_failed；滿 2 次 → XADD tasks:dead＋XACK＋kind=queue_task_dead。
  • 成功：寫 manifest.json（executed_by、steps、產物清單）→ XACK → kind=queue_task_done。
  • 事件 kind 全集：queue_task_taken|done|failed|dead|skipped|interrupt|interrupted|overrun、owners_dead|delayed|raw|xclaim、執行端錯誤 cc_busy|cc_timeout|cc_error_api|cc_error|cc_disabled|cc_unavailable|cc_malformed。

4.4 教練 ← 事件：nova:events

hs sync 用 task_id 對回清單，寫 status；不翻 passes。

5. 票（G）

  • 開票時機：hs open，一項功能一張票，沒票不派（ticket_gate hook 攔 dispatch）。
  • 票身：title [jvg] <behavior>；body 三段：行為句、驗收指令塊、來源（清單 id＋「passes 只准 check 翻」）。
  • 收單：check 綠 → 留言貼驗收輸出 → PATCH state=closed。紅 → 留言退回，hs dispatch --again。
  • 票號回寫清單 ticket；hs status 對不上會喊。

6. 搬家要換的東西（照順序做）

  1. 常數抽環境變數：HS_DIR、HS_REPO、VALKEY_*、GITEA_*、SHARED_ROOT（取代寫死的 /team）、RUNS_ROOT。
  2. 共享目錄：所有席位與橋掛同一個路徑；教練掛得到就把橋的兩步（落 spec、跑 submit）改成 hs 直呼，jvg:dispatch／jvg:dispatched 兩條 stream 可省。
  3. 執行端：把 /control 換成新機器的模型執行端；只要求三件事：吃 prompt 文字、cwd＝out_dir、回 ok／非 ok＋stdout。用 pi 就是 pi --mode rpc 或 pi -p（非互動模式不會問 project trust，.pi/ 資源要 --approve 或 defaultProjectTrust=always）。
  4. dgx: 前綴改名成 shared:（含意＝在共享目錄那側跑）。
  5. hooks（可選）：ticket_gate（沒票不派）、hands_gate（改程式檔要憑證）、discord_reply_guard 之類是教練端 harness 的，不屬於 jvg 本體。
  6. 第二階段：stall_watch（產物 30 分鐘沒 mtime → 票下留言＋告警）、heartbeat（每個 daemon 打卡，斷了喊）、tickets_page（票表發佈成網頁）。

7. 驗收（新機器上跑這幾條，全綠才算搬完）

  1. 正向 e2e：hs open demo-echo → hs dispatch demo-echo --timeout 120 --detail "在 out_dir 寫 REPORT.md 一行 ok" → 30 秒內 nova:events 出現 queue_task_taken 再 queue_task_done → hs sync 把 status 寫回 → hs check demo-echo 綠、passes=true → hs finish -m "demo" 產生一個 commit，票關閉。
  2. 沒票不派：清單項沒 ticket 時 hs dispatch 非零退出、隊列零訊息。
  3. 死信：expected 寫一個席位不會產的檔名 → 兩次失敗後 tasks:dead 有一筆、kind=queue_task_dead、清單 status 跟上、passes 仍 false。
  4. 人手翻不算：手改 passes=true → hs verify 抓出來。
  5. owners：--owners only:<不存在的席> → 進死信，理由 target_absent。
  6. 冪等：同 task_id 再投 → queue_task_skipped，不重跑。
  7. 三痕跡：沒 note 就 hs finish → 拒絕，無 commit。

8. 已知的坑（搬家時會再踩）

  • 席位回「收到開始執行」rc=0 但沒檔＝假交付；判成敗只看 expected_outputs 與 manifest，不看回應文字。
  • 教練那側的 pgrep 會自我匹配；判活用 pidfile＋/proc/<pid>/status State≠Z，不用 kill -0（殭屍會回成功）。
  • 派工端說 ok、執行端死信，兩邊都不喊：hs sync 要定期跑（或 cron），不能只靠 dispatch 回執。
  • 執行端逾時 rc 跟網路逾時同形（現行 rc=144）；先看 out_dir mtime 再定罪。
  • 第一版 stall_watch 用真資料誤報 18 張：起 daemon 前先乾跑數一次。

10. 核心精神與零服務版（Ray 2026-09-08 13:15 問「沒有 gitea 沒有 valkey 呢」）

精神：每件活留三個機器讀得懂的痕跡（票＝誰要什麼怎麼算過；隊列＝誰都能接走、有認領交回死信；清單＝一行一件、狀態由事件寫回），驗收綠燈只准機器翻，做完≠通過，判斷留教練、手腳交席位。

載體可換： - 票 → git repo 裡 tickets/<編號>.md（標題／驗收指令／狀態三段），或 GitHub issues。 - 隊列 → 共享目錄 inbox/、taken/<席位>/、done/、dead/；接活＝原子 mv；心跳＝touch hb/<席位>；兩次失敗 mv 進 dead/；席位每 30 秒掃 inbox/。 - 事件 → 只增不改的 events.log，一行一筆 JSON（ts, kind, task_id, consumer）；hs sync 改讀它。

現行實作裡交付資料夾本來就先於 valkey 訊息存在（01_submit_task.py 第 2 步），valkey 只是門鈴；拿掉門鈴只多延遲，流程不變。最小版本＝一個 git repo＋一個共享目錄，零服務。
